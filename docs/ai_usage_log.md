# AI 사용 기록

주간 보고서의 "AI 활용 기록" 항목에 쓰는 기록입니다. 취합: 이수빈.
AI를 쓸 때마다 **본인 이름 절 아래에** 한 건씩 추가해 주세요. 매주 1건 이상.

작성 요령
- **요청 내용**: AI에게 실제로 보낸 요청을 한두 문장으로. (예: "`..`가 들어오면 403을 내도록 고쳐 줘")
- **결과 확인 방법**: AI가 준 코드를 어떻게 검증했는지. 검증 사례 3개(정상·위반·경계) 실행 결과를 적으면 가장 좋음
- **채택·수정한 부분**: 그대로 쓴 것, 고친 것, 버린 것과 그 이유
- **막힌 점**: AI가 틀렸거나 오래 걸린 부분 (보고서의 한계·배운 점에 그대로 씀)

## 이수빈

### 11/18 (수) — 비교 웹 화면 첫 버전

| 항목 | 내용 |
|---|---|
| 도구 | Claude |
| 요청 내용 | 원논문, 구현 명세, 작업 계획, 저장소 링크를 주고 "비교 웹 화면 구성 작업을 시작해 줘"라고 요청 |
| 결과 | `web/app.py`(세 서버에 같은 요청을 동시에 보내 결과를 모아 주는 비교 서버, 포트 8000), `web/index.html`(3칸 비교 화면, 미끼 방 감시 기록, 요청 기록 표) |
| 결과 확인 방법 | 서버 ①②와 테스트용 임시 ③을 띄우고 검증 사례 3개를 화면과 `/api/compare`로 실행. 정상·경계는 세 서버 모두 공개 파일, 위반은 ① 진짜 유출(진짜 비밀번호 3개) / ② 403 / ③ 가짜 파일·진짜 비밀번호 0개·미끼 전환 "예"로 기대 결과표와 일치 |
| 채택·수정한 부분 | 브라우저가 8001~8003에 직접 요청하면 CORS로 막혀서, 다른 팀원 서버를 고치지 않고 비교 서버가 대신 요청하는 구조를 채택. 기존 서버처럼 표준 라이브러리만 사용(명세의 Flask 대신). ③이 꺼졌을 때 "미끼 이동: 아니요"로 잘못 보이던 것을 "해당 없음"으로 수정 |
| 막힌 점 | 화면이 모든 요청을 같은 IP(127.0.0.1)로 보내므로, ③이 IP로 공격자를 기억하면 공격 후 정상 요청까지 미끼로 갈 수 있음 → 정상 사용자 10.0.0.10, 공격자 10.0.0.66을 `X-Forwarded-For` 헤더로 구분해 보내도록 함. ③이 이 헤더를 읽어야 하므로 안지민과 맞춰야 함 |
